# SteelIQ – Lateral Enterprises

## Overview
SteelIQ is a professional quotation and estimating platform for the window and door industry. It automates and optimizes the quotation workflow with features such as item configuration, real-time visual representation via live SVG drawings, precise pricing, and efficient document generation. The platform includes comprehensive estimate and quote lifecycle management, detailed pricing breakdowns, and a flexible template-driven PDF engine. It supports organizational and division-specific settings, dynamic specification displays, and a project-centric CRM workflow, aiming to enhance accuracy and streamline operations. SteelIQ also supports a complete quote workflow for the Laser division, including manual item entry, snapshot persistence, and domain-specific preview and PDF rendering with a dedicated pricing engine.

## System Architecture
**Frontend**: Built with React and TypeScript, utilizing Shadcn UI for a responsive, mobile-first user experience.
**Backend**: Developed using Express.js, with a PostgreSQL database managed via Drizzle ORM and node-postgres.
**Drawing Engine**: Employs SVG for real-time technical drawing rendering and supports PNG export. Server-side drawing repair/regeneration (SVG to PNG) is handled without a browser DOM.
**State Management**: React state manages UI components, while TanStack Query handles API data fetching and caching. Global settings use React Context and localStorage.
**Routing**: Client-side navigation is managed by Wouter with a centralized route helper.
**Export Capabilities**: Supports SVG to PNG conversion and multi-page, vector-text selectable PDF generation using jsPDF, including specialized features for Subcontractor PDFs.
**Storage**: Item photos and drawing PNGs are stored in PostgreSQL (`bytea`), with an in-memory cache and filesystem mirror. Division logos are stored as base64 data URLs in PostgreSQL.
**Multi-Division Architecture**: Supports organizational and division-specific settings, including `domainType` to drive conditional UI behavior and domain-aware contracts for the quote/item/snapshot/render pipeline.
**Spec Dictionary System**: Provides configurable entries for dynamic display and override of specifications.
**Laser Division Workflow**: Supports a complete quote workflow for the Laser division, including manual item entry, snapshot persistence, and domain-specific preview and PDF rendering. It incorporates a detailed sheet materials library, a separate Laser pricing engine using time-based process costing (Phase 5B Bucketed Commercial Pricing), and a system for manual pricing overrides and provisional lines (Phase 5E). Pricing profiles are versioned, and source cost inputs are governed. A 4-tier precedence model determines pricing. Laser line items can also carry attached manual procedures (Folding/Deburring/Tapping/Other) priced manually/provisionally — these display as indented child sub-rows in the items table and as flattened sub-lines in the snapshot for PDF/Preview, while parent commercial overrides apply only to the laser base. Customer-facing Preview/PDF render manual + attached procedure pseudo-rows with labelled spec rows (Type / Procedure / Description / Attached To). Phase 5F also adds an LL Manual Blank Visual Placeholder: for laser items that have valid length+width but no uploaded drawing (and are not manual procedure pseudo-rows), the renderer emits `manualBlankPreview: { lengthMm, widthMm }` on `RenderScheduleItem`; both the customer Preview (SVG `ManualBlankPreviewSvg`) and the PDF (`pdf.roundedRect` + dimension caption + italic "Indicative blank only" muted caption) render a simple proportional rectangle outline in the existing left visual area. No DXF/CAD parsing, no nesting/uploads, no new DB fields, and no math/workflow/cost/margin/supplier/bucket exposure — uses only existing snapshot dimensions. Pagination estimator includes the placeholder height (bounded by `drawingMaxH`) so cross-page parity is preserved. Phase 5F adds: (A) LL estimate→quote update/revision workflow mirroring LJ — converted estimates expose three header actions (Open Quote / Update Existing Quote / Create New Quote) with Save remaining enabled; the server resolves the revision target deterministically (explicit `sourceQuoteId` first, with linkage validation against `sourceLaserEstimateId`/`sourceJobId`/`divisionCode`; falls back to source-id lookup, newest for LL, oldest for LJ). (B) Commercial override "Markup % on cost" mode (uncapped values >100; true margin remains output-only via `finalMarginPercent`; `target_margin` still rejects values >=100 with a message pointing to the new mode). (C) Attached procedures display as compact operation rows nested INSIDE the parent item card in customer Preview and PDF (Phase 5F polish): the renderer collapses each attached child into its parent's `attachedOperations` array (Procedure / Description / Qty + optional Unit Price / Line Total) and filters the children out of the top-level schedule list, so the customer sees one card per parent with an "Operations" subsection. The verbose "Type Attached Manual / Provisional Procedure" and "Attached To 002" rows are removed; standalone manual procedures (no attached parent) still render as their own top-level cards. Operation pricing follows the existing per-revision "Item Unit Price" / "Item Line Total" toggles; snapshot totals are unaffected because they are computed from `snapshot.totalsBreakdown`, not from the rendered card list. The PDF U+21B3 (`↳`) glyph that was rendering as `!³` (jsPDF helvetica is Latin-1 only) has been removed from every PDF code path; the new Operations block uses ASCII / Latin-1-safe characters only. Phase 5F also includes a Preview/PDF Pagination Parity fix: the Customer Quote Preview previously hardcoded `ITEMS_FIRST_PAGE = 1` so page 1 carried at most one schedule item, while the PDF used height-based pagination — this caused the preview to push subsequent items onto a second visual page even when the exported PDF correctly fit them on page 1. The preview now uses a measurement-based packer that mirrors the PDF's per-item density formula (`itemHeaderH` / `specRowH` / `drawingMaxH` / `photoRowH` plus pane-glass and attached-operations heights), estimates the page-1 chrome (header / disclaimer / customer-project / totals / remarks with wrap-aware text estimation / schedule heading / inter-section gaps), and greedily packs items into pages using A4 content-height budgets. The first item on any page is always placed (matching the PDF's `ensureSpace` "place oversized item" behaviour). Overflow pages get the full A4 content budget (PDF does not re-render the schedule heading on overflow pages). The change is render-side only — pricing, totals, snapshot logic, attached-operation collapsing, and PDF generation are untouched. (D) LL Add Item builder display-clarity hardening (LABEL-ONLY; no math change): bucket panel columns relabelled "Line Buy"/"Line Sell" under "Bucket (line totals)"; "Unit Sell" annotated "(line ÷ qty)"; "Sheet price (ex-GST)" relabelled "Supplier sheet buy (ex-GST)" with explanatory tooltip; "Estimated sheets" annotated "(procurement)" with footnote stating yield-based billing; Commercial Override section title is dynamic — "Commercial Pricing Preview / (override OFF — engine-calculated values shown below)" when toggle is off and "Commercial Override Active / (override ON — manual values applied)" when on. Customer-facing Preview/PDF and supplier governance untouched. Two optional per-revision Display-Settings toggles ("Item Unit Price" and "Item Line Total", LL only, default OFF) surface per-line sell-side pricing inside the existing item spec table without exposing cost / margin / supplier / internal notes.
**Quote Management**: Features a comprehensive lifecycle (Draft, Review, Sent, Accepted/Declined, Archived) with atomic sequential numbering, immutable revision history, and server-side status enforcement. Each quote includes an `EstimateSnapshot` for immutable revision data.
**Pricing System**: Calculates material, labor, glass, liner, and handle costs, providing net cost, sale price, and margin. Supports manual price override, removal/rubbish fees, markup application, GOS charges, and geometry-aware pricing.
**Master Library Systems**: Centralized libraries for direct materials, manufacturing labor, installation labor, and delivery methods, with controls for active status and default designations.
**CRM Workflow**: Project-centric CRM with automatic customer linking from quotes, project creation linked to quotes, and sub-query endpoints. Projects have persisted `projectNumber` (PRJ-XXXX format) auto-assigned via server-side sequence on creation. Accepted LL quotes auto-match or auto-create CRM customers and include a 4-step delivery workflow stepper. A lightweight 7-stage workflow strip (Estimate → Quote → Accepted → Customer → Project → Job → Invoice) is integrated across detail pages for visibility.
**Invoice Management**: Manages invoices with detailed line items, full CRUD operations, automated status demotion, and Xero integration.
**UI/UX**: Features responsive tables, polished spec row formatting in PDFs, project dashboard guidance, customer relink safeguards, and an enterprise app shell with workflow-domain grouped navigation. Standardized list page headers, row styling, and `max-w-7xl` width for settings/users pages. Governance systems support archive/delete with chain-aware safety guards, and audit activity tables use business-facing identifiers.

- **React**: UI library.
- **TypeScript**: Statically typed JavaScript.
- **Shadcn UI**: UI component library.
- **TanStack Query**: Data fetching and caching library.
- **Wouter**: Routing library.
- **jsPDF**: Client-side PDF generation library.
- **multer**: Middleware for handling `multipart/form-data`.
- **sharp**: High-performance image processing for server-side SVG to PNG rendering.
- **Xero**: Accounting software integration for payment visibility and status readback.
